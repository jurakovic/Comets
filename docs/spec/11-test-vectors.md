# 11 — Test vectors

[`vectors/`](vectors/) holds expected results generated by running the **desktop sources**, linked unchanged, through [`tools/spec-vectors`](../../tools/spec-vectors/). A web implementation conforms when it reproduces them within the tolerances below.

## Frame of reference

| | |
|---|---|
| Clock | Frozen at **2026-10-18 12:00:00 UTC** (`JD 2461332.0`). Every "now", "today", `Tn` and `Current*` value refers to it. |
| Time zone | UTC, except the one local-time ephemeris case, which is `Europe/Zagreb` |
| Observer | Latitude 0, longitude 0, unless a case says otherwise |
| Data | MPC `Soft00Cmt` … `Soft16Cmt` and JPL `ELEMENTS.COMET`, downloaded 2026-10-18 |
| Text | Stored with LF line endings and UTF-8 without BOM. The app writes CRLF, so compare after normalizing. |

To reproduce the vectors, the implementation's clock, time zone and observer MUST be injectable. Pure modules SHOULD take `now` and the observer as parameters rather than reading globals.

The sample collection deliberately includes:

- numbered periodic comets, defunct (`D`) comets, fragments (`73P-BT`, `96P-B`, `141P-A`, `3D-A`, `C/1947 X1-B`, `C/2023 R1-B`) and interstellar objects (`1I`, `2I`, `3I`);
- `A/` objects, an old-style designation (`C/1942 EA`), and q ≥ 10 AU (`C/2014 UN271`, `C/2019 E3`);
- P > 30000 years (`C/1999 F1`), near-parabolic hyperbolas (`C/2013 A1`) and a short day fraction (`18D`);
- five **synthetic** comets: an exact parabola `C/2026 T99 (Parabola Test)`, a negative year `C/-146 P1`, an `X/` type `X/1106 C1`, and digit fragments `D/1993 F2-A`, `C/1860 D1-A`.

## Tolerances

| Quantity | Tolerance |
|---|---|
| JD values (`time.json`, `T`, `Tn`) | 1·10⁻⁸ day |
| Instants (`jdToDate`, `TnDate`, simulation steps) | Exact |
| Parsed element values | Exact (float64 parsing of the same text). Computed ones (xephem `q`, MyStars `w`, NASA angles): 1·10⁻⁹ |
| Derived P, a, Q, n | Relative 1·10⁻¹² |
| Angles (RA, Dec, Alt, Az, EcLon, EcLat, Elongation, PositionAngle) | 1·10⁻⁶ °, compared modulo 360 |
| Distances (SunDist, EarthDist, planet and comet coordinates) | 1·10⁻⁸ AU |
| Magnitudes | 1·10⁻⁸ |
| Orbit-sampling points | Exact count; coordinates 1·10⁻⁹ AU |
| Graph x values | 1/86400 day (the desktop chart stores whole seconds) |
| Strings: names, sort keys, export text, detection results, lists of `full` | Exact |

### Ephemeris text

Text vectors are compared **exactly**. If a line differs, it is acceptable only when:

- the differing field is off by one unit in its last printed digit, and
- recomputing that value shows it lies within 1·10⁻⁹ (relative) of a rounding boundary of its format.

Any other difference is a defect.

### Ordering

Lists produced by sorting or filtering MUST match exactly. If two comets' sort values differ by less than 1·10⁻¹² (relative), either order is acceptable. No such pair exists in the current vectors.

## Conformance plan

1. **Unit level (Node).** Structure the code so that time, astronomy, name parsing, formatting, import, export, filter and sort modules are DOM-free ES modules. Run them under `node --test` against every vector file above. This is the gate for every change.
2. **Worker level.** Run the ephemeris and graph pipelines through the same Worker message interface the UI uses, and check `ephemeris-text/` and `graph.json`.
3. **UI level.** Use browser tests (e.g. Playwright, pre-installed in this repository's cloud environment) for the scripted flows:
   - first-run download, against a stub server or a fixture file;
   - import preview counts against `import-merge.json`;
   - database filters against `filters.json`;
   - ephemeris save against `ephemeris-text/`.
4. **Visual level.** Compare orbit viewer screenshots at fixed camera, date and display settings against reference images produced by the web app itself once accepted. The desktop renderer differs, for example in fonts. Checklist: ecliptic colour split, zoom-dependent planet hiding, magnitude colours and sizes, markers, labels, grid fading, axes and labels, weak colour.

## Regenerating

See [`tools/spec-vectors/README.md`](../../tools/spec-vectors/README.md). Re-running with the committed inputs reproduces the committed vectors byte for byte.
