# Comets — working notes for Claude

This repository holds the desktop app (`src/`, C# WinForms, .NET 8) and its rebuild as a client-only web app (`app/`, vanilla HTML, CSS and ES modules on GitHub Pages). Sessions work on the web app.

`docs/spec/` is the source of truth: `README.md` indexes it, `12-architecture.md` says how the code is organised. Read the sections relevant to your task before writing code, and cite them (`spec 04, Time`) in code comments only where the reason is not obvious. If the spec is wrong or ambiguous, fix the spec in the same commit and say so in the commit message.

`docs/plan.md` tracks milestones and items. Tick items off as they land and add decisions to its log.

The desktop app is the reference for behaviour: web work does not change `src/`. The vectors in `docs/spec/vectors/` are generated by `tools/spec-vectors/` from the desktop sources; never edit them by hand.

## Layout

```
app/                     the web app, served as is (Pages: /Comets/app/)
  index.html, css/, img/
  js/main.js             composition root: the only module that knows every layer
  js/lib/                generic helpers (store, emitter, rpc)
  js/core/               domain and engine: pure, DOM-free, deterministic
                         (time, format, comets, astro, formats, ephemeris, graph, orbit; jobs.js)
  js/services/           use cases and app state; ports.js names the ports
  js/adapters/           the ports implemented with browser APIs
  js/workers/            Worker entry points
  js/ui/                 shell/, components/, views/<view>/
tests/unit/              node --test, mirroring app/js
tests/vectors/           node --test, one file per vector file
tests/helpers/           vector loading, tolerance assertions, fakes
tests/e2e/               Playwright, offline (fixtures.js), desktop and phone
tests/serve.js           the repository under /Comets/, as Pages serves it
docs/spec/               the spec (01–12) and its vectors/
docs/plan.md             milestones, items, decision log
docs/manual-test.md      checks on real browsers and devices, per milestone
docs/review-*.md         review findings
tools/spec-vectors/      generates the vectors from the desktop sources
src/                     the desktop app
```

| What | Command |
|---|---|

To look at a UI change, run `npm run screenshots` and open the PNGs; CI uploads the same set as the `comets-screenshots` artifact. Regenerating the vectors needs .NET 8 and libfaketime, which cloud sessions do not have until asked: `apt-get install -y faketime`, then `curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 8.0` and `export PATH=$HOME/.dotnet:$PATH`. A plain run reproduces the committed vectors byte for byte; CI's Spec vectors workflow checks that.

CI (`.github/workflows/`): **Web** runs the gate and the screenshots on `dev`, `master` and pull requests; **Spec vectors** regenerates the vectors when the generator, the vectors or the desktop engine change. Both run only when their inputs change (`paths`), so docs-only commits trigger neither. The desktop's **Publish** workflow is the user's.

## Sessions

Sessions are short: one plan item each, so the context stays small.

When asked for the **implementation status** (e.g. "give me implementation status"), change nothing. Read `docs/plan.md` and the latest CI runs on `dev`, then report briefly: the current milestone and how far it is, the items done most recently, the next item, CI's state, and anything waiting on the user (decisions, manual checks).

When asked to **continue** (e.g. "continue with implementation"):

1. Work on `dev`: `git fetch origin dev && git checkout dev && git pull --ff-only origin dev`.
2. Check the latest Web and Spec vectors runs on `dev` (GitHub tools, repository `jurakovic/Comets`). If one is red, fixing it is this session's work.
3. Otherwise take the first `[ ]` item in `docs/plan.md` and do only that item.
4. Commit and push, tick the item (and log decisions) in the plan, then stop and report briefly. Do not start the next item.

If an item turns out too big for one session, split it in the plan, finish the first part and stop.

Reviews: after an item that warrants it, one reviewer on its `git diff` plus a few key files. A broader review closes each milestone as its own plan item, with its findings in `docs/review-m<N>.md`.

## Conventions

- **Architecture** (spec 12): the dependency rule between `lib`, `core`, `services`, `adapters`, `workers` and `ui`, which lint and types enforce; never silence them, change the design instead. `core` is plain frozen data and functions, and takes `now`, the time zone and the observer as parameters. Services reach the outside world through ports and never ask the user. Views are humble: what to show comes from pure functions. Registries instead of `switch`es on a kind. One owner per piece of state.
- **JavaScript**: ES2022 modules, named exports, `.js` in every import path, kebab-case file names, nothing named with a leading `_` or `.` (Jekyll skips it on Pages). JSDoc types on every exported function; shared shapes are `@typedef`s in the module that owns them. No runtime dependencies, nothing from a CDN.
- **Spec texts** (labels, messages, file names, output formats) are copied exactly.
- **Tests**: a pure module comes with its vector or unit tests in the same commit. A bug fix comes with a test that fails without the fix; prove it by running the test against the unfixed code.
- **Files**: LF and tabs for `app/` and `tests/` (`.editorconfig`); YAML and `package.json` use two spaces. Desktop files keep their CRLF; edit them with the editor tool, since `sed -i` rewrites line endings.

### JavaScript against .NET

The vectors come from .NET, and JavaScript differs in ways that pass casual tests:

- `toFixed` rounds the binary value; .NET formats round the 15-digit decimal half away from zero. Use `core/format` (lint bans `toFixed`).
- `substr` and `slice` return what there is on a short line; the importers must fail there (spec 03, Field access; lint bans `substr`).
- `Math.round` rounds halves up; .NET `Math.Round` rounds them to even (`roundEven`).
- `parseFloat` and `Number` accept text .NET rejects and the reverse; parse with the strict rules of spec 03, Field access.
- `Date.UTC` and `new Date(y, …)` map years 0–99 to 1900–1999; set the year with `setUTCFullYear` for any year.
- `%` keeps the dividend's sign, as in C#; JD formulas use `Math.floor`, which differs from truncation for negative values.
- Strings sort with `compareText` (`core/comets/collation.js`: `Intl.Collator('en')`, the root order), not `<`, a default-locale `localeCompare` or `Intl.Collator('und')`, which falls back to the host's locale; `Array.prototype.sort` is stable, which spec 02 relies on.

## Comments

The spec says what the app does and why; a code comment explains the code it sits on.

- **A module header** is one to three lines: what the module is, then its spec section (`docs/spec/04-astronomy.md, Time`).
- **A comment by the code** gives what the code cannot say: a guard's reason, an ordering constraint, a browser quirk, a number's origin, a desktop quirk kept on purpose (`spec 10, Q5`).
- **Only what is true now**: no history, no plan item ids, no earlier implementations.
- Lowercase prose fragments naming what the thing is (`// the nearest perihelion to now: …`), full sentences in headers, about 100 columns.
