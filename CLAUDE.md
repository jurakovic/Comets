# Comets — working notes for Claude

This repository holds the desktop app (`src/`, C# WinForms, .NET 8) and its rebuild as a client-only web app (`app/`, vanilla HTML, CSS and ES modules on GitHub Pages). Sessions work on the web app.

`INTERNALS.md` describes how the web app is built: its layers and the dependency rule, the core, services and ports, state, storage, the Worker, the UI, testing and the test vectors. Read the sections relevant to your task before writing code. It describes the code as it is, and nothing else: no decisions, no history, no plans.

The desktop app is the reference for behaviour: web work does not change `src/`. The vectors in `tests/vectors/data/` are generated by `tools/spec-vectors/` from the desktop sources; never edit them by hand.

## Layout

```
app/                     the web app, served as is (Pages: /Comets/app/)
  index.html, css/
  js/main.js             composition root: the only module that knows every layer
  js/lib/                generic helpers (store, queue, rpc, math)
  js/core/               domain and engine: pure, DOM-free, deterministic
                         (time, format, comets, astro, formats, ephemeris, graph, orbit, input;
                         jobs.js, validation.js)
  js/services/           use cases and app state; ports.js names the ports
  js/adapters/           the ports implemented with browser APIs
  js/workers/            Worker entry points
  js/ui/                 shell/, components/, views/<view>/
tests/unit/              node --test, mirroring app/js
tests/vectors/           node --test, one file per vector file
tests/vectors/data/      the test vectors, generated from the desktop sources
tests/helpers/           vector loading, tolerance assertions, fakes
tests/e2e/               Playwright, offline (fixtures.js), desktop and phone
tests/serve.js           the repository under /Comets/, as Pages serves it
tools/spec-vectors/      generates the vectors from the desktop sources
INTERNALS.md             how the web app's code is built, as it is now
docs/                    notes on the desktop app's rendering, DPI and simulation
src/                     the desktop app
```

## Commands

| What | Command |
|---|---|
| Install the tooling (the session hook does it) | `npm ci` |
| Lint, with the layer rules | `npm run lint` |
| Types (JSDoc, strict, per layer) | `npm run typecheck` |
| Unit and vector tests | `npm test` |
| One test file | `node --test tests/vectors/time.test.js` |
| Browser tests (desktop and phone Chromium) | `npm run test:e2e` |
| The gate: all of the above | `npm run check` |
| Every view in both themes to `test-results/screenshots/*.png` | `npm run screenshots` |
| Serve the app at `http://127.0.0.1:8085/Comets/app/` | `npm run serve` |
| Regenerate the vectors | `tools/spec-vectors/run.sh` |

To look at a UI change, run `npm run screenshots` and open the PNGs; CI uploads the same set as the `comets-screenshots` artifact. Regenerating the vectors needs .NET 8 and libfaketime, which cloud sessions do not have until asked: `apt-get install -y faketime`, then `curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 8.0` and `export PATH=$HOME/.dotnet:$PATH`. A plain run reproduces the committed vectors byte for byte; CI's Spec vectors workflow checks that.

CI (`.github/workflows/`): **Web** runs the gate and the screenshots on `dev`, `master` and pull requests; **Spec vectors** regenerates the vectors when the generator, the vectors or the desktop engine change. Both run only when their inputs change (`paths`), so docs-only commits trigger neither. The desktop's **Publish** workflow is the user's.

## Conventions

- **Architecture** (`INTERNALS.md`): the dependency rule between `lib`, `core`, `services`, `adapters`, `workers` and `ui`, which lint and types enforce; never silence them, change the design instead. `core` is plain frozen data and functions, and takes `now`, the time zone and the observer as parameters. Services reach the outside world through ports and never ask the user. Views are humble: what to show comes from pure functions. Registries instead of `switch`es on a kind. One owner per piece of state.
- **JavaScript**: ES2022 modules, named exports, `.js` in every import path, kebab-case file names, nothing named with a leading `_` or `.` (Jekyll skips it on Pages). JSDoc types on every exported function; shared shapes are `@typedef`s in the module that owns them. No runtime dependencies, nothing from a CDN.
- **Fixed texts** (labels, messages, file names, output formats) are exact: the desktop's wherever it has one, and the vectors check the output formats. Change one only on purpose, never in passing.
- **Tests**: a pure module comes with its vector or unit tests in the same commit. A bug fix comes with a test that fails without the fix; prove it by running the test against the unfixed code.
- **Files**: LF and tabs for `app/` and `tests/` (`.editorconfig`); YAML and `package.json` use two spaces. Desktop files keep their CRLF; edit them with the editor tool, since `sed -i` rewrites line endings.

### JavaScript against .NET

The vectors come from .NET, and JavaScript differs in ways that pass casual tests:

- `toFixed` rounds the binary value; .NET formats round the 15-digit decimal half away from zero. Use `core/format` (lint bans `toFixed`).
- `substr` and `slice` return what there is on a short line; the importers must fail there (the field access of `core/formats/text.js`; lint bans `substr`).
- `Math.round` rounds halves up; .NET `Math.Round` rounds them to even (`roundEven`).
- `parseFloat` and `Number` accept text .NET rejects and the reverse; parse with `core/format/parse.js`, as .NET reads numbers.
- `Date.UTC` and `new Date(y, …)` map years 0–99 to 1900–1999; set the year with `setUTCFullYear` for any year.
- `%` keeps the dividend's sign, as in C#; JD formulas use `Math.floor`, which differs from truncation for negative values.
- Strings sort with `compareText` (`core/comets/collation.js`: `Intl.Collator('en')`, the root order), not `<`, a default-locale `localeCompare` or `Intl.Collator('und')`, which falls back to the host's locale; `Array.prototype.sort` is stable, which sorting relies on.

## Comments

`INTERNALS.md` says how the code is built; a code comment explains the code it sits on.

- **A module header** is one to three lines: what the module is, then the `INTERNALS.md` section that describes it, where one does (`INTERNALS.md, Storage`).
- **A comment by the code** gives what the code cannot say: a guard's reason, an ordering constraint, a browser quirk, a number's origin, a desktop behaviour matched on purpose (`as on the desktop`) or a deliberate difference from the desktop (`where the desktop throws`). Desktop names (`CometManager`, `ExportMpc00`) say which desktop source a rule comes from.
- **Only what is true now**: no history, no task or decision ids, no earlier implementations.
- Lowercase prose fragments naming what the thing is (`// the nearest perihelion to now: …`), full sentences in headers, about 100 columns.
